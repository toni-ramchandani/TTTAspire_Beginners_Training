What the criterion does not require
  • classification does not have to equal ACCESS.

Trainer narration

Display Runs 1, 3, and 4 from Day 1. Ask learners to separate the raw interface, intended meaning, and release disposition. Run 3 has acceptable meaning but an invalid raw transport because Markdown fences surround the JSON. Run 4 has valid raw structure but violates the safety contract. The phrase “passed” is incomplete unless we name the criterion.

Move through the funnel from product goal to threshold. The product goal can remain broad, but an executable evaluation objective must name the behavior, evidence, and scope. The criterion then identifies observable conditions. The metric implements those conditions, and the threshold converts its score into criterion-level success or failure.

Emphasize that 4 of 5 is an expected teaching result, not the success threshold. Each case still uses a strict binary threshold. The cohort-level 80 percent is a descriptive result across five prepared outputs. A release gate would require several criteria, risk-based blocking rules, and a representative dataset.

If asked: criterion versus metric

A criterion is the quality condition written in product or evaluation language. A metric is the procedure that produces evidence about that criterion. Several metrics may operationalize one criterion, and one metric may be reused across many cases. Treating a framework metric name as the product requirement reverses the design process.

Trainer narration

        
Explain why the primary artifact is day2_eval.py rather than a notebook. Day 1 already uses lab_day1.py. Keeping a normal script means the interpreter begins from a clean state on every run, execution order is visible, diffs are reviewable, and the same code can later move into a test suite or CI pipeline. If asked: why the adapter exists
The DeepEval documentation says the model is used only to generate a failure reason when include_reason is true. During clean verification of 4.1.3, constructing JsonCorrectnessMetric without an explicit model still attempted default client initialization. Passing a DeepEvalBaseLLM implementation satisfies that constructor path. Its generate methods raise immediately, so an accidental model call fails closed instead of accessing a provider.

Trainer narration

        
Walk from left to right. The Day 1 files provide auditable evidence. Each LLMTestCase represents one atomic request-response interaction. The metric defines one measurement procedure. strict_mode sets the criterion-level threshold to a binary 1. evaluate executes the metric across the five test cases and returns per-case evidence. The product decision then combines this result with other safety and business criteria; it is not delegated to JsonCorrectnessMetric.

        
Review evidence legality. The original request maps to input and the unmodified response maps to actual_output. We do not need expected_output because the criterion is not exact sentence similarity. We do not add retrieval_context or tools_called because Day 1 did not capture those runtime artifacts. Framework fields are invitations to supply evidence, not permission to manufacture it.

        
Contrast deterministic and model-based metrics. Deterministic evaluators use parsing, schemas, exact rules, or calculations and should return the same result for the same evidence and implementation. Model-based evaluators use an LLM judge, adding prompt design, model/version control, nondeterminism, calibration, cost, latency, and privacy concerns. Day 2 implements only the first category.

        
If asked: DeepEval use cases
DeepEval supports end-to-end and component-level evaluation for LLM applications, including RAG, agents, safety, and multi-turn systems. It is useful for Python teams that want explicit test cases and evaluators in local or CI-connected workflows. It should not replace requirement discovery, human calibration, representative dataset design, or product-level release governance.

Trainer narration

        
Give learners ninety seconds to write a result statement before revealing the reference answer. Require the sentence to name the cohort, metric criterion, observed result, failure cause, and unevaluated dimensions. Correct any claim that says the assistant is 80 percent accurate or that Run 4 passed without naming the schema criterion.

If asked: when does a metric become a gate?
A metric becomes part of a gate only after the team maps it to a requirement, validates the implementation, establishes a dataset and slices, chooses thresholds from risk and empirical evidence, defines blocking versus advisory behavior, and verifies that automated results maintain acceptable agreement with trusted human judgment.

Trainer question bank
          
Why preserve the human labels? They provide an independent evidence layer and later support judge calibration. They are not inserted into a field the schema metric does not use.

          
Why not implement all eight Day 1 checks again? Day 1 already proved those rules. Day 2's new learning outcome is framework anatomy, execution, and bounded interpretation.

          
Why can the schema evaluator pass malicious content? A schema constrains shape and types, not meaning. Unsafe strings can be perfectly schema-valid.

          
When should the team move to deepeval test run? When evals become regression tests with assertion semantics, parametrization, repeatable test selection, and CI reporting.
